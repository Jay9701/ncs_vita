# UI 공통 규칙

## 1. 기본 원칙

- 모바일 우선(Mobile First)으로 설계한다.
- 320px~390px 폭에서도 주요 정보가 보이도록 한다.
- 텍스트가 넘치면 줄바꿈, 축소, 2줄 제한, 말줄임순으로 우선순위를 둔다.
- 요소는 화면이 좁아질수록 세로 배치와 카드 압축을 우선한다.
- 모든 화면은 작은 화면 기준으로 안전하게 보이도록 검증한다.

## 2. 반응형 기준

### 권장 기준
- 320px: 최소 안전 구역
- 360px: 기본 스마트폰 기준
- 390px: 일반적인 최신 스마트폰 기준
- 412px: 큰 스마트폰 기준

### 체크 원칙
- 텍스트가 카드 폭을 넘지 않는지
- 버튼이 화면 하단 여백을 침범하지 않는지
- 2줄 이상이 필요한 값은 줄바꿈 허용 여부를 명확히 정하고, 글자 크기를 조정하는지
- 목록/카드 전체가 화면 높이를 초과하지 않는지

## 3. 타이포 규칙

### 중요: 글씨 크기 설정값 우선
- 앱에 `fontScale` 또는 비슷한 설정이 있으면, 텍스트는 고정 px로 잡지 않는다.
- 기본 기준은 `Theme.of(context).textTheme` 또는 `fontScale` 기반 배율을 사용한다.
- 화면이 좁아지거나 사용자가 글자 크기를 조정했을 때도 자연스럽게 줄어들거나 늘어나야 한다.
- 고정 크기 값은 예외적으로 매우 작은 UI 요소(아이콘 라벨, 디버그 텍스트)에서만 사용한다.

### 제목
- 메인 제목: 기본 텍스트 스케일 기준 18~20px 근처, Bold
- 섹션 제목: 기본 텍스트 스케일 기준 16~18px 근처, Bold
- 작은 제목/라벨: 기본 텍스트 스케일 기준 12~13px 근처, SemiBold

### 본문/값
- 값 텍스트: 기본 스케일 × 1.0~1.3 범위에서 조절
- 작은 값/설명: 기본 스케일 × 0.8~1.0 범위에서 조절
- 한글 문구는 카드의 폭이 좁아질수록 2줄 허용을 우선한다.
- 긴 라벨은 축약, 줄바꿈, 혹은 짧은 표현으로 재구성한다.
- 작은 화면에서는 `fontScale`을 그대로 무조건 적용하지 않고, `clamp`로 최소/최대 범위를 정해 깨짐을 방지한다.

## 4. 카드 규칙

- 카드 내부 패딩은 기본 12~16px로 통일한다.
- 카드 간 간격은 12px~16px로 유지한다.
- 카드 높이는 내용이 많아도 화면을 밀지 않도록 유동적으로 조정한다.
- 긴 텍스트라면 카드 내부 정렬을 center로 유지하고, 줄 높이와 font size를 함께 조정한다.
- 카드 제목과 값 사이 간격은 최소 4px~8px 유지.

## 5. 버튼 규칙

- 주요 CTA 버튼은 넓고 가독성 있게 유지한다.
- 작은 조작 버튼(화살표, 증감)은 28~32px 크기를 기본으로 한다.
- 꽉 찬 버튼형 UI는 화면 너비를 초과하지 않도록 한다.
- 너무 많은 인라인 버튼이 붙어있으면 2개 이상을 세로 그룹으로 분리한다.

## 6. 옵션 선택 UI 규칙

- 값 선택 카드에서 긴 한글 값은 2줄 이하로 제한한다.
- 값 텍스트는 기본적으로 center 정렬한다.
- 값이 길면 `maxLines`, `softWrap`, `overflow` 조합을 우선 적용한다.
- 좌/우 증감 버튼은 고정 폭을 유지하고, 값 영역이 가장 유연하게 줄어들도록 한다.

### 예시
- 유형: `덧셈/뺄셈`, `분수 비교`와 같은 긴 label은 2줄 허용
- 난이도/문항수/타이머: 숫자 값은 보통 1줄 유지

## 7. 스크린별 우선순위

### 홈 화면
- 상단 요약과 CTA는 항상 보이도록 한다.
- 카드가 길어지면 설명 텍스트는 축소하거나 숨긴다.

### 연습 화면
- 선택 옵션 카드 2개 열 기준으로 유지한다.
- 긴 옵션 값은 줄바꿈과 축소를 허용한다.
- 옵션 카드는 각 화면에서 깨지지 않는 최소 높이를 보장한다.

### 게임 화면
- 문제 수/타이머/입력 영역은 화면을 넘기지 않도록 한다.
- 입력 버튼과 숫자 패드는 크기와 간격을 조절해 터치 오버랩 방지.
- 답 입력 영역은 1줄 기준으로 유지한다.

### 결과 화면
- 점수 요약은 핵심만 큰 글자로 보여준다.
- 버튼 영역은 하단 고정 배치로 안전하게 유지한다.

## 8. 검증 체크리스트

- 320px에서 텍스트가 잘리지 않는가?
- 360px에서 버튼이 화면 밖으로 나가지 않는가?
- 카드는 균형 잡힌 높이와 간격을 유지하는가?
- 긴 한글 label이 2줄 이내로 자연스럽게 보이는가?
- 터치 영역이 충분히 눌리는가?
- 주요 정보가 제대로 보이는가?

## 9. 작업 규칙

- 공통 스타일을 한번 정한 뒤, 각 화면은 그 규칙을 우선 적용한다.
- 화면별 예외는 최소화한다.
- 새 UI를 만들 때는 반드시 작은 화면 기준으로 먼저 검증한다.
- 실제 기기나 에뮬레이터별로 3개 이상 폭을 점검한다.

## 10. 최종 목표

- 앱 전체가 같은 디자인 언어를 공유한다.
- 작은 화면에서도 자연스럽게 보인다.
- 기능과 시각 모두 안정적으로 유지한다.
- “깨진 UI”를 사전에 방지한다.
